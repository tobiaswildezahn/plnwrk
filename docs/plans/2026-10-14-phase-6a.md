# Phase 6a – MCP-Server: Implementierungsplan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Claude Code (und Claude Desktop) bedient plnwrk-Dateien über MCP: Projekte auswerten,
Aufgaben anlegen und ändern, Termine verschieben (Nachfolger rutschen mit), alles rückgängig
machbar und im Verlauf als „durch KI“ markiert.

**Entscheidungen (Tobi, 2026-10-14):**
- 6b (Assistent in der App) ist **bis auf Weiteres ausgesetzt**.
- **Kein VS-NfD über MCP:** harte Sperre (Datei, Verlauf und jeder Befehl, der darauf hebt).
- **Jede Datei:** Claude nennt den Pfad je Aufruf; es gibt keine feste Datei und keinen Ordner.
- **Lesen und Schreiben:** Jede Änderung wird sofort gespeichert und ist ein Rückgängig-Schritt.
  Im Verlauf ist sie mit `Origin::Assistant` als „durch KI“ markiert.
- **Verschlüsselte Dateien nicht über MCP:** Die Passphrase stünde sonst im Klartext in der
  Einrichtung, und der Inhalt ginge an einen KI-Dienst.
- Eine Datei, die in der App geöffnet ist, wird klar abgelehnt (vorhandene Dateisperre).
  Gleichzeitiges Arbeiten ist Phase 9.
- Terminänderungen über MCP schieben Nachfolger wie in der Oberfläche.

**Architecture:**
- **`plnwrk-mcp` (Schicht 3, nur nativ):** MCP über stdio als zeilenweises JSON-RPC 2.0.
  - **Ohne `rmcp`:** Abweichung von PLAN §4. Die benötigte Protokollfläche ist klein (initialize,
    ping, tools/list, tools/call). `rmcp` brächte tokio und async in eine synchrone Codebasis.
    Ein reiner Handler `Server::handle(&mut self, line) -> Option<String>` ist vollständig ohne
    Prozess testbar.
  - **Protokollversionen** `2025-06-18`, `2025-03-26`, `2024-11-05`: Die erbetene wird
    beantwortet, wenn bekannt, sonst die neueste.
  - **Fehler:** Unbekannte Methode -32601, kaputtes JSON -32700, falsche Parameter -32602.
    Fehler eines Werkzeugs kommen als Ergebnis mit `isError: true` und Begründung (für das
    Modell lesbar).
  - **`instructions`** (Antwort auf initialize) erklären das Modell: Datei per absolutem Pfad,
    IDs aus Abfragen, Daten `JJJJ-MM-TT`, `undo` nimmt den letzten Schritt zurück, kein VS-NfD.
- **Werkzeuge** (jedes mit Pfad `file`, außer der Befehlssuche):
  - `overview(file)`: Projekte und Vorgänge mit Fortschritt (Abfrage `overview`).
  - `query(file, name, params?)`: jede Abfrage aus `query_registry`. Die Beschreibung des
    Werkzeugs listet die Namen samt Zweck.
  - `search_commands(words?)`: Befehle mit Zweck und JSON-Schema der Parameter.
  - `run_command(file, command, params?)`: jeder Befehl. Er wird gespeichert und als ein
    Rückgängig-Schritt geführt. `task.update` mit Beginn/Frist läuft über `task.reschedule`
    samt Schub der Nachfolger.
- **Datei je Aufruf:**
  1. Pfad auflösen (Verknüpfungen folgen).
  2. Kopf lesen (`peek`): verschlüsselt → ab; Einstufung ≥ VS-NfD → ab.
  3. Laden, dann Inhalt und Verlauf prüfen (`classification_of`).
  4. Nur zum Schreiben: Sperre setzen (belegt → „in plnwrk geöffnet“), Befehl prüfen, ausführen,
     atomar speichern, Sperre freigeben.
  - Ältere Dateiformate werden wie in der CLI hochgestuft.
- **Gemeinsame Logik, aus der Oberfläche herausgezogen:**
  - `plnwrk_engine::asks_for_classified(params)`: VS-Prüfung vor dem Ausführen, für Browser
    und MCP.
  - `plnwrk_schedule::reschedule(ws, task, start, due) -> Vec<Move>`: Schub für die Oberfläche
    und für MCP.
- **CLI:** `plnwrk-cli mcp` startet den Server (stdin/stdout, Meldungen nach stderr).
- **Einrichten:**
  - Installation: `cargo install --path apps/plnwrk-cli --locked`.
  - Claude Code: `claude mcp add plnwrk -- plnwrk-cli mcp`.
  - Claude Desktop: Eintrag in `claude_desktop_config.json`, als Anleitung in `docs/mcp.md`.

## Global Constraints
- Kein `unwrap`/`panic` in Produktionscode; jede Eingabe ist feindlich (Zeilen, JSON, Typen, Pfade).
- Sperren und Prüfungen **vor** `Session::run`.
- Nichts außer `.plnwrk`-Dateien wird je geschrieben. Lesefehler verraten keinen Dateiinhalt.
- Neuer Crate in `NATIVE_ONLY` (`xtask/src/ci.rs`); Schichtregel L3 → darf engine/store/schedule.

## Review Focus
1. **VS-NfD:** Eine Datei mit NfD im Kopf, nur im Verlauf oder durch einen Befehl, der auf NfD
   hebt: Nichts wird gelesen oder ausgegeben, die Datei bleibt Byte für Byte gleich.
2. **Feindliche Eingaben:** riesige Zeilen, kaputtes JSON, falsche Typen, ein Pfad auf eine
   Nicht-plnwrk-Datei oder ein Verzeichnis. Erwartet wird eine saubere Fehlermeldung ohne
   Absturz, und es wird nie fremd geschrieben.
3. **App und MCP gleichzeitig:** Ist die Datei in der App offen, lehnt MCP Schreiben klar ab.
   Lesen zeigt den gespeicherten Stand und sagt das.
4. **Termine:** Claude verschiebt eine Frist über `task.update`. Die Nachfolger rutschen mit,
   ein `undo` nimmt alles zurück.
5. **Protokoll:** Notification ohne Antwort, unbekannte Methode, `tools/call` auf unbekanntes
   Werkzeug, Batch-Arrays (nicht unterstützt → Fehler statt Stille).

# Phase 3a – Desktop-MVP: Implementierungsplan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Eine Desktop-App, mit der Tobi auf seinem Mac mit Beispieldaten echte Arbeit
durchspielen kann: Datei anlegen/öffnen/speichern, Projekte und Vorgänge (auch aus Vorlage)
anlegen, Aufgaben mit Unteraufgaben, Meilensteine, Board mit Drag & Drop, Detailansicht mit
Kommentaren und Verlauf, Rückgängig/Wiederholen.

**Entscheidung (Tobi, 2026-10-14, STATUS 4.4):** Früh etwas Zeigbares; volle VS-Umsetzung später.
Test auf dem eigenen Mac, mit ausgedachten Daten. Deshalb wird Phase 3 geteilt:
**3a MVP** (dieser Plan) und **3b** (Befehlspalette, Englisch, Inline-Bearbeitung in der Liste,
Autosave/Wiederherstellung, Verschlüsseln aus der App, Theme-Umschalter).

**Architecture:** `plnwrk-ui` (Schicht 4) liest typisiert über die Abfragefunktionen der Engine
(`overview`, `board`, `tasks`, `history` …) und ändert ausschließlich über `Session::run`. Dateien
laufen über `plnwrk-store`; Dateidialoge kommen über einen `Host`-Trait von außen (Desktop: `rfd`,
Tests: Attrappe), damit `ui` für wasm32 baut und ohne Fenster testbar bleibt. Uhr und Zufall
wandern aus der CLI in einen neuen Crate `plnwrk-platform` (Schicht 2).

**Tech Stack:** egui/eframe 0.36 (mit `persistence`), rfd 0.17 (nur Desktop-App),
egui_kittest 0.36 (Oberflächentests über den Barrierefreiheitsbaum).

**Spec:** [docs/PLAN.md](../PLAN.md) §3.6, §7 Phase 3; Entscheidung oben.

## Global Constraints

- Nur `Session::run` ändert Daten; die Oberfläche hat keine eigene Fachlogik.
- Never crash: keine `unwrap`/`expect`/Indexzugriffe; Fehler eines Befehls erscheinen als
  Meldung in der Statusleiste, die App läuft weiter.
- `plnwrk-ui` baut für wasm32 (kein `rfd`, kein `std::fs` außer über `plnwrk_store::file`).
- Oberflächentexte zentral in `crates/ui/src/text.rs` (Deutsch); Englisch folgt in 3b.
- Eine geöffnete Datei ist für andere plnwrk-Prozesse gesperrt (`store::file::lock`).
- Ungespeicherte Änderungen gehen nie still verloren (Schließen, Öffnen, Neu fragen nach).

## Review Focus

1. **Fehlschlagender Befehl** (z. B. Frist ungültig, leerer Titel) → Meldung, Daten unverändert,
   Eingabe bleibt stehen (Task 4/6).
2. **Tastenkürzel im Textfeld:** Cmd+Z im Textfeld darf nicht die letzte Datenänderung
   zurücknehmen (Task 2).
3. **Datei weg/gesperrt/kaputt beim Öffnen** → Meldung, bisherige Datei bleibt offen (Task 2).
4. **Ziehen auf die eigene Position / leere Spalte** → keine oder genau eine Änderung (Task 5).
5. **Auswahl verschwindet** (Aufgabe gelöscht, Rückgängig nach Anlegen) → Detailansicht schließt
   sich, kein Fehler (Task 6).

## Demo für Tobi (ohne Rust-Wissen)

1. Terminal: `cd ~/projekte/plnwrk && cargo xtask app` (dauert beim ersten Mal ein paar Minuten),
   dann `open target/plnwrk.app` – oder im Finder `plnwrk/target/plnwrk.app` doppelklicken.
2. **Beispiel öffnen** → Übersicht mit einem Projekt und einem Vorgang, darunter Überfälliges.
3. Links **+ Neu** → Titel, Art „Vorgang“, Aktenzeichen, Frist → **Anlegen**.
4. In der Liste unten eine Aufgabe tippen, Enter; mit **+** neben einer Aufgabe eine
   Unteraufgabe anlegen; Haken setzt sie auf erledigt.
5. Reiter **Meilensteine** → Titel und Datum (TT.MM.JJJJ) → **+ Meilenstein**.
6. Reiter **Board** → Karte mit der Maus in eine andere Spalte ziehen; Klick auf eine Karte
   öffnet rechts die Details (Status, Zuständig, Frist, Kommentare, Verlauf).
7. Links **+ Aus Vorlage** → Vorlage „SKA beantworten“, Titel, Aktenzeichen, Frist → ein
   Vorgang mit allen Schritten der Vorlage entsteht.
8. **⟲ Rückgängig** (oder Cmd+Z) nimmt Schritt für Schritt zurück, **⟳ Wiederholen** stellt her.
9. **Cmd+S** → Ort wählen → Datei schließen (Menü Datei) → auf der Startseite unter „Zuletzt
   geöffnet“ wieder öffnen. Beim Schließen mit ungespeicherten Änderungen fragt plnwrk nach.

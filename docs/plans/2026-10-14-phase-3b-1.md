# Phase 3b-1 – Termine und Meilensteine: Implementierungsplan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Datumsauswahl an jedem Datumsfeld, Fristen mit optionaler Uhrzeit, Meilensteine als
Aufgaben – ohne dass vorhandene Dateien unlesbar werden.

**Entscheidungen (Tobi, 2026-10-14, nach dem MVP-Test):**
1. Jedes Datumsfeld bekommt eine Datumsauswahl (Kalender).
2. Fristen können eine Uhrzeit haben – **überall optional** (Projekt, Vorgang, Aufgabe); ohne
   Uhrzeit gilt „bis Tagesende“. Bei Vorgängen (Projekt mit Aktenzeichen) zeigt die Oberfläche
   das Uhrzeitfeld gleich mit, sonst auf Klick.
3. **Ein Modell für Meilensteine:** Ein Meilenstein *ist* eine Aufgabe mit Merkmal
   `milestone` (nur oberste Ebene, keine Unteraufgaben). Erreicht = erledigt. Die eigene
   Meilenstein-Entität entfällt für neue Daten; vorhandene werden beim Öffnen umgewandelt.

**Architecture:**
- `core`: `Task.milestone: bool`, `Task.due_time`, `Project.due_time` (`Option<civil::Time>`),
  alle mit `#[serde(default, skip_serializing_if = …)]` – alte Daten serialisieren
  **byte-gleich**, damit Hash-Kette und „Replay = Momentaufnahme“ für Dateien v1 halten.
  Invarianten: Meilenstein hat keinen `parent` und keine Kinder; `due_time` nur mit `due`.
  `Clock::now_local() -> civil::DateTime` für Verzug mit Uhrzeit.
- `engine`: Parameter `due` nimmt `YYYY-MM-DD` oder `YYYY-MM-DDTHH:MM` (ein Feld für Mensch und
  Agent; Datum ohne Zeit löscht die Uhrzeit). `task.create/update` mit `milestone`.
  Neuer Befehl `workspace.upgrade` (Origin::Script) wandelt alle `Milestone`-Entitäten in
  Meilenstein-Aufgaben um (eine Änderung im Protokoll, Geschichte bleibt). `milestone.*`
  bleiben registriert (nötig, um alte Protokolle zu prüfen), sind aber **gesperrt**
  (`Disabled`: „ersetzt durch Aufgaben mit milestone“) und erscheinen nicht in `commands`.
  Abfragen (`overview`, `project`, `overdue`, Board/Liste) lesen Meilensteine aus Aufgaben;
  Verzug vergleicht Datum+Uhrzeit mit `now_local`. Vorlagen kopieren Meilenstein-Aufgaben samt
  Uhrzeit. Fixture ohne `milestone.create`.
- `store`: `manifest::VERSION = 2` (ältere plnwrk melden „neuere Version“ statt „beschädigt“);
  v1 wird gelesen wie bisher. Exporte zeigen Uhrzeit und ♦.
- `ui`: Widget `date_field` (Textfeld + 📅-Knopf mit Monatskalender, Mo–So, heute markiert,
  „Heute“/„Leeren“) und optional `time`-Feld (HH:MM). Überall, wo Daten getippt werden.
  Aufgabe: Haken „Meilenstein“ (nur oberste Ebene) in Details und beim Anlegen; ♦ in Liste und
  Board. Reiter „Meilensteine“ zeigt die Meilenstein-Aufgaben. Beim Öffnen einer Datei mit alten
  Meilensteinen: `workspace.upgrade` und Hinweis „auf neues Format umgestellt – bitte speichern“.
- `cli`: `run`/`query` wie gehabt; beim Ändern einer v1-Datei mit Meilensteinen läuft
  `workspace.upgrade` mit.

## Global Constraints

- Dateien aus Phase 2/3a (Version 1) öffnen weiterhin ohne Fehler; Test mit einer echten,
  vorab gespeicherten v1-Datei (Fixture-Datei im Repo).
- Uhrzeiten sind Ortszeit (bürgerliche Zeit, ohne Zeitzone gespeichert): eine Frist „14:00“
  bleibt 14:00, egal wo die Datei geöffnet wird.
- Never crash, Befehle nur über `Session::run`, Junk-Fuzzer erfasst neue Parameter.

## Review Focus

1. **Alte Datei** mit Meilensteinen (unverschlüsselt und verschlüsselt) öffnen, umwandeln,
   speichern, wieder öffnen – Kette, Replay und Einstufung stimmen.
2. **Uhrzeit-Grenzen:** Frist heute 14:00 → um 13:59 nicht, um 14:01 überfällig; Frist ohne
   Uhrzeit erst morgen überfällig.
3. **Meilenstein umhängen:** Aufgabe mit Unteraufgaben zum Meilenstein machen, Meilenstein
   unter eine Aufgabe hängen → abgelehnt mit klarer Meldung.
4. **Undo über `workspace.upgrade`** bringt die alten Meilensteine zurück (oder wird klar
   verhindert) – kein halber Zustand.
5. **Datumsauswahl** im Februar/Schaltjahr, Monatswechsel, Leeren, Tastatureingabe parallel.

## Demo für Tobi

1. `cd ~/projekte/plnwrk && git checkout phase-3b && cargo xtask app && open target/plnwrk.app`
2. **Beispiel öffnen** → Projekt „Digitalfunk“ → Liste: „♦ Zuschlag erteilt“ und
   „♦ Inbetriebnahme“ (15.12.2026 10:00) sind jetzt Aufgaben; Reiter **Meilensteine** zeigt sie.
3. Links **+ Neu** → bei Frist auf **📅** klicken → Tag wählen; **🕑** fügt eine Uhrzeit hinzu.
   Mit Aktenzeichen (Vorgang) ist das Uhrzeitfeld gleich da.
4. Eine Aufgabe anklicken → rechts Haken **Meilenstein** setzen → in der Liste erscheint ♦.
   Bei Unteraufgaben ist der Haken gesperrt.
5. Eine Datei aus Phase 3a öffnen → Hinweis „auf neues Format umgestellt“ → speichern.

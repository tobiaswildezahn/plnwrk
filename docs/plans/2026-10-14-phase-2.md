# Phase 2 – Speicherung: Implementierungsplan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ein Arbeitsbereich wird als `.plnwrk`-Datei gespeichert und geladen – optional bzw. bei
VS-NfD zwingend verschlüsselt, mit Hash-Kette über das Änderungsprotokoll und vollständiger
Prüfung beim Laden. Die CLI arbeitet damit auf echten Dateien.

**Architecture:** `plnwrk-store` (Schicht 2) arbeitet nur auf Bytes (`save → Vec<u8>`,
`load(&[u8])`) und bleibt damit browserfähig; Dateizugriff (atomares Schreiben) liegt in einem
nativen Modul `store::file`. Eine Datei ist immer ein ZIP mit lesbarem `manifest.json`. Ohne
Verschlüsselung liegen daneben `workspace.json` (Momentaufnahme) und `log.jsonl` (Änderungen mit
Hash-Kette); mit Verschlüsselung liegen diese in einem inneren ZIP, das als `payload.age`
(age, Passphrase/scrypt) abgelegt ist. Beim Laden wird das Log von leer an wieder abgespielt;
das Ergebnis muss der Momentaufnahme exakt entsprechen.

**Tech Stack:** zip 9 (deflate, reines Rust), age 0.12 (scrypt), blake3, rpassword (nur CLI).

**Spec:** [docs/PLAN.md](../PLAN.md) §3.4, §3.8, §7 Phase 2.

## Global Constraints

- `plnwrk-store` baut für wasm32 (nicht in `NATIVE_ONLY`); `std::fs` nur im Modul `file`
  hinter `#[cfg(not(target_arch = "wasm32"))]`.
- Dateien sind feindlich: Größenlimits (Standard 256 MiB entpackt, 64 Einträge), kein Panic bei
  beliebigen Bytes; jeder Fehler ist ein `StoreError` mit klarer Ursache.
- Einstufung ≥ VS-NfD (irgendein Projekt oder eine Aufgabe) ⇒ Speichern nur verschlüsselt;
  eine unverschlüsselte Datei mit VS-NfD-Inhalt wird beim Laden abgelehnt.
- Die lesbare Kopfzeile (äußeres Manifest) enthält Format, Version, Einstufung,
  Verschlüsselt-ja/nein – keine Inhalte, keine Titel.
- Formatversion 1. Neuere Versionen → `NewerFormat`; Migrationsrahmen vorhanden.
- Ehrlichkeit: Die Hash-Kette erkennt Beschädigung und naive Manipulation; gegen gezielte
  Manipulation einer **unverschlüsselten** Datei schützt erst eine Signatur (Phase 7). In der
  verschlüsselten Datei sichert age die Unversehrtheit (authentifizierte Verschlüsselung).

## Review Focus

1. **Beschädigte oder fremde Datei** (abgeschnitten, Bytes gekippt, kein ZIP, leeres ZIP,
   ZIP-Bombe) → `StoreError`, nie Panic, nie still „halbe“ Daten (Task 3, Fuzz).
2. **Manipuliertes Log oder Momentaufnahme** (Ereignis geändert, Zeile entfernt, Kette neu
   berechnet aber Snapshot alt) → erkannt (Task 2/3).
3. **Falsche oder fehlende Passphrase** → `WrongPassphrase` bzw. `PassphraseRequired`, keine
   Teildaten (Task 4).
4. **Herabstufung**: VS-NfD-Inhalt unverschlüsselt speichern oder laden, äußeres Manifest mit
   zu niedriger Einstufung → abgelehnt (Task 4).
5. **Absturz beim Speichern** → alte Datei bleibt unversehrt (atomares Schreiben, Task 5).

### Task 2: Manifest, Hash-Kette, Replay

**Interfaces:**
```rust
pub struct Manifest { pub format: String /* "plnwrk" */, pub version: u32, pub classification: Classification,
  pub encrypted: bool, pub created_with: String, pub saved_at: Timestamp,
  pub changes: u64, pub head: Option<String> /* blake3 hex of last log line */ }
pub const FORMAT: &str = "plnwrk"; pub const VERSION: u32 = 1;
pub struct SealedLine { pub change: Change, pub prev: String, pub hash: String }
pub fn seal(log: &[Change]) -> Result<Vec<String> /* jsonl lines */, StoreError>;
pub fn unseal(lines: &str, expected_head: Option<&str>) -> Result<Vec<Change>, StoreError>;
pub fn replay(log: &[Change]) -> Result<Workspace, StoreError>;   // Seq 1..n lückenlos, Events per apply
```
hash = blake3(prev_hash_hex || "\n" || canonical_json(change)); erste Zeile prev = 64×"0".

- [ ] Tests: Kette rund; geänderte Zeile → `ChainBroken{seq}`; entfernte letzte Zeile →
  `ChainBroken` (Kopf passt nicht); vertauschte Zeilen → Fehler; Seq-Lücke → `Corrupt`;
  Replay einer Fixture-Session = deren Arbeitsbereich; Replay mit falschem `before` → `Corrupt`.

### Task 3: Container ohne Verschlüsselung

**Interfaces:**
```rust

pub enum Protection { None, Passphrase(SecretString) }
pub struct Limits { pub max_bytes: u64, pub max_entries: usize }   // Default 256 MiB, 64
pub fn save(doc: &Document, protection: &Protection) -> Result<Vec<u8>, StoreError>;
pub fn peek(bytes: &[u8]) -> Result<Manifest, StoreError>;
pub fn load(bytes: &[u8], passphrase: Option<&SecretString>) -> Result<Document, StoreError>;
pub fn load_with(bytes, passphrase, limits: Limits) -> Result<Document, StoreError>;
```
Laden prüft: Manifest (Format, Version), Kette, Replay = Snapshot, `check()` leer,
Einstufungsregeln.

- [ ] Tests: Round-Trip der Fixture (Workspace und Log identisch, danach weiterarbeiten + Undo
  möglich auf neuen Changes); `peek` ohne Passphrase; nur Snapshot manipuliert →
  `SnapshotMismatch`; Kette konsistent neu berechnet, Snapshot alt → `SnapshotMismatch`;
  Version 2 → `NewerFormat`; fremdes ZIP → `NotPlnwrk`; Zufallsbytes / abgeschnitten /
  gekippte Bytes (proptest) → `Err` oder (falls die Änderung nur Unkritisches traf) exakt
  dasselbe Dokument; Limits klein gesetzt → `TooLarge`.

### Task 4: Verschlüsselung und Einstufung

- [ ] `Protection::Passphrase` → äußeres ZIP mit `manifest.json` + `payload.age`; innen das

  Manifest dem äußeren entsprechen.
- [ ] scrypt-Arbeitsfaktor: Standard des age-Crates; Tests nutzen niedrigen Faktor über
  `save_with(…, SaveOptions { work_factor: Some(10) })`.
- [ ] Tests: Round-Trip verschlüsselt; falsche Passphrase → `WrongPassphrase`; keine →
  `PassphraseRequired`; VS-NfD ohne Schutz speichern → `ClassifiedUnencrypted`; unverschlüsselte

  auf „open“ herabgesetzt → `Corrupt`; ein Byte in `payload.age` gekippt → Fehler.

# Phase 4 – Web: Implementierungsplan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Dieselbe App läuft im Browser mit derselben Datei wie auf dem Desktop: hochladen,
bearbeiten, herunterladen. Ein Zwischenstand übersteht ein Neuladen. VS-NfD ist im Browser
hart gesperrt.

**Entscheidung (Tobi, 2026-10-14, STATUS 4.1):** „im Browser erstmal eine harte Sperre für
VS-NfD“.

**Architecture:**
- **Dateien ohne Pfade:** Der `Host`-Trait (`crates/ui/src/host.rs`) bekommt einen
  Browser-Modus.
  - `browser()` meldet den Modus.
  - `request_upload()` öffnet die Dateiauswahl, die Datei kommt später über `uploaded()`;
    die App fragt das in jedem Bild ab.
  - `download(name, bytes)` speichert über einen Download.
  - `set_leave_warning(bool)` steuert die Rückfrage beim Verlassen der Seite.
  - Die App-Logik dafür liegt in `plnwrk-ui` ohne `cfg(wasm32)`. Sie läuft darum auch in den
    nativen Tests (Testwirt `Scripted` mit Browser-Modus). Nur die JavaScript-Anbindung liegt
    in `apps/plnwrk-web` (web-sys).
- **Öffnen:**
  - Eine hochgeladene Datei wird `FileAction::Upload { name, bytes }`; die Rückfrage bei
    ungespeicherten Änderungen gilt wie gewohnt.
  - Der Passphrase-Dialog arbeitet auf einer `FileSource` (Pfad oder hochgeladene Bytes).
  - Der Arbeitsbereich heißt wie die Datei.
- **Speichern** (und „Speichern unter…“) im Browser = Herunterladen als `<Name>.plnwrk`.
  Danach gilt die Datei als gespeichert. Es gibt keine „Zuletzt geöffnet“-Liste und kein
  „Beenden“.
- **VS-NfD-Sperre (Browser):**
  1. Beim Öffnen liest die App die Einstufung aus dem lesbaren Kopf (`plnwrk_store::peek`)
     und lehnt VS-NfD ab, bevor sie nach einer Passphrase fragt.
  2. Nach dem Laden prüft sie den Inhalt noch einmal.
  3. Hebt ein Befehl den Arbeitsbereich auf VS-NfD, wird er sofort zurückgenommen und
     gemeldet.
  4. Ein Hinweis auf der Startseite und in der Statuszeile sagt, dass der Browser nicht
     VS-geeignet ist (PLAN §3.8).
- **Zwischenstand im Browser:**
  - Bei ungespeicherter Arbeit legt `eframe::App::save` den Stand in den eframe-Speicher
    (`localStorage`), als Base64 unter `plnwrk.recovery`, mit Namen.
  - eframe ruft das alle 10 s (eigenes `auto_save_interval`) und beim Verlassen der Seite.
  - Beim Start bietet die Startseite den Stand unter „Wiederherstellen“ an. Speichern oder
    Verwerfen löscht ihn.
  - Verschlüsselte Arbeitsbereiche werden nicht zwischengespeichert: Verschlüsseln kostet im
    Browser Sekunden, und Klartext gehört nicht in den Browser-Speicher. Die Statuszeile
    sagt das.
  - **Abweichung vom Plan:** `localStorage` über eframe statt eigener IndexedDB-Anbindung,
    weil es kleiner und synchron ist und für Dateien bis wenige MB reicht.
- **Verlassen der Seite:** Bei ungespeicherter Arbeit fragt der Browser über `beforeunload`
  nach.
- **Veröffentlichung:** Ein GitHub-Actions-Job `pages` baut das Web-Paket und veröffentlicht
  es auf GitHub Pages. Er startet nur von Hand (`workflow_dispatch`). Das erste
  Veröffentlichen braucht Tobis Freigabe (öffentliche Adresse, Pages-Einstellung im Repo).

## Global Constraints
- Kein Netzzugriff: Dateien gehen nur durch Upload und Download, keine Daten an Server.
- Never crash. Nichts ohne Rückfrage verwerfen.
- Browser-spezifischer Code nur in `apps/plnwrk-web`; Logik testbar in `plnwrk-ui`.

## Review Focus
1. Eine VS-NfD-Datei mit falschem Kopf (Kopf „offen“, Inhalt VS-NfD) wird trotzdem abgelehnt.
2. Hochladen, während ungespeicherte Arbeit offen ist: Rückfrage, die Datei geht nicht verloren.
3. Speichern im Browser gelingt (Download angestoßen) und gilt nur dann als gespeichert.
4. Zwischenstand nach Neuladen: wird angeboten, öffnet als ungespeichert, verschwindet nach
   Speichern oder Verwerfen. Ein kaputter Zwischenstand bringt die App nicht zum Absturz.
5. Der Browser-Speicher ist voll oder nicht verfügbar: Hinweis statt Absturz.

## Demo für Tobi

1. `cd ~/projekte/plnwrk/apps/plnwrk-web && trunk serve`, dann http://127.0.0.1:8080 öffnen.
2. Am Desktop eine Datei speichern, im Browser „Datei öffnen…“ wählen und dieselbe Datei
   hochladen, etwas ändern, „Speichern“ → die Datei liegt im Download-Ordner und öffnet
   wieder am Desktop.
3. Etwas ändern, Seite neu laden (Rückfrage) → beim Start steht der Zwischenstand unter
   „Wiederherstellen“.
4. Eine VS-NfD-Datei hochladen → abgelehnt mit Hinweis.
